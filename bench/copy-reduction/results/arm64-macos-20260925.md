# Copy-reduction implementation audit, 2026-09-25

Candidate: uncommitted copy-reduction work on `2a4198f0`.

Baseline: unchanged `635de296` in an independent worktree.

Machine: Apple M5 Pro, 48 GiB, arm64 macOS 26.6 (Darwin 25.6.0), Rust 1.98.0.

## Retained copy paths

| Path | Payload movement after this change | Why the remaining movement exists |
| --- | --- | --- |
| TCP `readSpan` / `readInto` | The socket syscall fills final Nupp storage after a bounded prefetched prefix is drained | The kernel must copy received bytes into user memory. The prefix may already have entered the old bounded read-ahead queue before the first direct call. |
| TCP write | Nupp storage is borrowed synchronously; Rust makes one owned queue copy | The async writer must own bytes after the Nupp call returns. No borrowed pointer crosses suspension. |
| Split stream reads/writes | Same as the owning stream | The views share the same native capability and do not add payload staging. |
| Datagram receive | Kernel -> owned queued datagram -> final Nupp storage | Arrival is asynchronous and preserves message boundaries, address and truncation state; the final drain is one bulk copy and no clone. |
| File `readInto` | Kernel/file API -> final Buffer lease | No provider scratch or Lua string remains. |
| HTTP response | Hyper-owned body chunk -> final Nupp storage | The response task owns chunks asynchronously; consumption is one native bulk copy. |
| HTTP upload | Nupp span -> one Rust-owned request chunk | Reqwest may use the body after the Nupp call returns. Redirects reuse one owned inline-Buffer snapshot. |
| TLS receive | Kernel -> rustls record storage; rustls plaintext -> final Nupp storage | Rustls owns encrypted and decrypted protocol state. Its public reader copies available plaintext to the caller; there is no temporary payload `Vec`, TLS inbound queue, FFI scratch or Lua string. |
| TLS send | Nupp plaintext -> rustls; rustls ciphertext -> one network ownership queue | Encryption creates new bytes, and the async network writer must own them. Rustls keeps unsent ciphertext on `WouldBlock`; no second TLS queue exists. |
| Process output | Kernel -> fixed Rust scratch -> bounded Rust queue -> final Nupp storage | A background task must own pipe output across suspension. The queue drain is bulk, including wraparound, rather than one `pop_front` per byte. Replacing the queue with owned chunks remains a separate representation change. |
| Process input | Nupp span -> one Rust-owned queue value | The child writer is asynchronous. Pointer-plus-offset polling creates no suffix strings. |
| One-shot decompression | Borrowed compressed span -> decoder -> final Buffer leases | Codec state and the decoded result are distinct data. There is no Lua input string, StringReader refill, or output scratch-to-Buffer copy. |
| Built-in digest | Full blocks are read from the borrowed span; at most one partial block is copied | A digest must retain an incomplete block after `update` returns, when the borrowed input is gone. Final string results still materialize explicitly. |
| Scalar reader | One stable backing plus a cursor; only a split fixed-width scalar's few bytes are retained | Streaming chunks may end within a scalar. The old repeated unread-tail substring is gone; explicit `readBytes` still materializes its requested string. |

Audited string-to-destination adapters now perform zero per-byte Lua loop
iterations. Legacy string-returning APIs still allocate the requested string;
their span/Buffer counterparts do not route through those strings.

## Deliberately rejected conditional changes

- Direct scalar writers were flat to slightly slower, so the representation-wide
  codec changes were dropped.
- `ByteView:view()` remains eager: six-byte slicing and UTF-8 walking were flat,
  while a lazy view would require cache and large-backing retention policy.
- `QueueReader` keeps its opaque `get()` fallback. There is no built-in lua51
  queue exposing a direct drain to justify a duck-typed hot path.
- String and queue transfers keep their all-or-nothing retry behavior. Network,
  TLS and process transfers keep their existing timeout/high-water chunking, and
  HTTP keeps its 16 MiB fairness yield. No shared lowest-common-denominator loop
  was introduced.

These decisions avoid a LuaJIT fork, fabricated external Lua strings, retained
foreign pointers, and mutable aliases of immutable snapshots.

## Specialized benchmark verdicts

The 1 MiB built-in SHA-256 span case was effectively flat: one paired fork
reported +0.24% duration, below the 3% practical margin. Normalized allocation
fell from 0.000005092 to 0.000004805 KiB per input byte. The mechanism is still
retained because full input blocks now create no payload-proportional temporary
strings and only the sub-block tail survives the call.

The stabilized 1 MiB span-to-Buffer decompression case was also flat: three
paired forks reported +0.92% duration, below the 3% practical margin. The
duration verdict is inconclusive because the benchmark requires more than
three forks for a statistical verdict. Its copy accounting is complete above;
the path is retained for eliminating the extra workspaces without a practical
duration regression, not claimed as a speedup.

The separately recorded native-runtime results contain the demonstrated
throughput wins. The largest are 3.39x for a 16 MiB TCP Buffer read, 7.22x for
a 16 MiB HTTP Buffer read, 1.67x for a 4 MiB TLS Buffer/span echo, and 14.70x
for repeated scalar parsing.

## Bounded-resource result

`bench/native-runtime/resource.sh` stayed bounded on the candidate:

```text
load peak_rss_kib=67344
net-slow-reader second=1/3/5 rss_kib=51616/51776/51920
net-slow-writer second=1/3/5 rss_kib=50400/50576/50784
http-slow-reader second=1/3/5 rss_kib=52592/52720/52864
http-slow-writer second=1/3/5 rss_kib=62304/63152/63152
```

The plateau, rather than the absolute process RSS, is the bounded-buffering
signal. Process-wide RSS is not attributed to LuaJIT, the host or a Rust
provider.
