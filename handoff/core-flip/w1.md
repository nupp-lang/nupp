## Gotchas
- One harness at a time; selections reach ~9 GB. Before running, check `pgrep -fl core-selfbuild` and
  for `fixpoint --runtime core`, but filter out `zsh -c` waiter shells: pgrep -f matches them too.
- bin/nupp no longer exports NUPP_ZLIB/CRC_LIBRARY. The runner on the core traps (`brk 0xf0`, missing
  symbol) without NUPP_CRC_LIBRARY; acceptance.nupp and runnerinventory.lua name them from
  scripts/c-library-paths.
- testrunner normal/spill share the runner result cache: keep `--fresh`.
- An edit under src/ or tests/core while a harness runs makes later steps rebuild or miss caches;
  a rebase mid-sweep changed bootstraptest.lua (its row may be off).
- Pre-push hook: a NEW branch is diffed from merge-base with origin/main (all of core-dev). Create the
  remote ref at your base first (`gh api repos/nupp-lang/nupp/git/refs -f ref=refs/heads/X -f sha=BASE`),
  then push normally. Don't use --no-verify.
- nupp-planning commits: edit tasks.md, `node ~/projects/avoozl/cli.mjs generate --workspace .`, then
  `node scripts/repository.mjs export`, commit both through the hook. Spec tasks are issue-owned, so
  `avoozl update` refuses them. A stray ignored .nupp-cache in that checkout gets indexed: moved to
  /tmp/w1probe/planning-stray-nupp-cache.
- Inventory regeneration is byte-identical; failing rows keep their owner. New failures get "unowned",
  which --ci rejects.
