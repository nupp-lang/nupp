# Trace-aware LuaJIT checking

Status: implemented for the compiler-owned host profile and initial catalog. The
reason registry, exact bytecode check, transported `@jit` contract, normalized runtime
report, one-shot LSP query, and VS Code command are shipped without instrumenting
ordinary programs. Further target/catalog entries and automated cross-report ranking
remain evidence-gated T5 additions rather than guessed rules.

## Decision

Build one trace-reason engine that combines facts from checked source, generated
bytecode, the selected pinned LuaJIT recorder, and optional observed trace events.
Use it through three existing surfaces:

- `nupp bc --check` statically reports unconditional recorder blockers in the exact
  generated artifact and exits 1;
- `@jit` makes those blockers non-suppressible contract errors in the annotated
  function and its statically resolved checked callees; and
- `nupp run --jit-aborts` attaches the existing VM trace hook and reports what the
  recorder actually refused in that run, normalized through the same reason registry.

Ordinary check, build, and run inject no counters, probes, callbacks, zone operations,
or alternate bytecode. Static checking reads compiler facts and emitted bytecode.
Runtime observation remains opt-in and uses `jit.attach(..., "trace")`; its callback
cost exists only while the trace session is active. Zones remain optional attribution,
not a prerequisite for a trace verdict.

The engine must not promise that a function will execute as machine code. A loop may
never run, may stay cold, may take runtime types the recorder cannot specialize, or
may side-exit for input-dependent reasons. It can make narrower exact claims:

- an **unconditional blocker** makes recording abort whenever the pinned recorder
  reaches that operation;
- a **must-reach blocker** is an unconditional blocker on every repeatable path through
  the named loop, so that loop cannot complete a root trace;
- a **may-reach blocker** is unconditional once reached but lies on only some paths, so
  a trace taking that path aborts while another path may compile;
- a **conditional risk** depends on runtime types, call targets, shapes, limits, or
  target details and is advisory;
- an **observed abort** came from the VM hook in this execution; and
- an **expected stop** is ordinary trace completion, recursion, or loop exit and is
  informational rather than a failure.

Every diagnostic says which class it is. Absence of a static blocker means no known
unconditional blocker in the catalog, not proof of runtime compilation.

## Goal

Turn LuaJIT's silent performance cliffs into source-level, repairable explanations
without duplicating optimizations the recorder already performs. The motivating cases
are loops that build functions, variadic FFI, callbacks that cannot re-enter Lua from
a trace, polymorphic call sites that explode into traces, unstable table shapes, and
compiler lowerings that accidentally introduce unrecordable bytecode.

A representative answer should join the authored operation, emitted artifact, and
runtime evidence without confusing them:

```text
src/physics.nupp:42:5: NUPP2515 jit-loop-closure
this loop builds a function and cannot be recorded by the selected LuaJIT

  static       unconditional blocker: FNEW at generated bytecode 31
  source       closure captures `body` from this iteration
  observed     7 aborts; loop blacklisted in zone frame/physics
  help         pass the varying value to one function declared outside the loop
```

The static part is deterministic and sufficient for CI. The observed lines appear only
when a trace report is being correlated.

## Existing baseline

Nupp already has the necessary pieces, but they answer separately:

- `@jit` rejects known variadic/callback FFI boundaries and loop-built closures;
- `jit-boundary` (`NUPP2514`) and `jit-loop-closure` (`NUPP2515`) expose the same
  hazards as configurable lints;
- `nupp bc --check` reads bytecode rather than timing a program and finds loop closure
  construction introduced by user source or lowering;
- `nupp run --jit-aborts` aggregates `jit.attach` trace events by reason, source line,
  severity, and optional zone;
- sampling reports whether a hot frame ran native, interpreted, in C, in GC, or in the
  compiler; and
- effects, call resolution, identity-based intrinsics, generated source-line
  preservation, and optimization remarks already provide source facts and repairs.

Do not replace any of these with another profiler or command that disagrees. Factor
their overlapping decisions into one reason engine, then widen its catalog.

## Non-goals

- Do not fork LuaJIT, parse its textual `-j` output, or maintain an independent model
  of its complete optimizer.
- Do not inject source counters, edge probes, loop callbacks, or hidden zone pushes in
  ordinary or trace-checked builds.
- Do not claim that a function is hot, will be called, will form exactly one trace, or
  will stay compiled for every input.
- Do not report every side exit or ordinary trace stop as a problem.
- Do not make a general cost model, instruction scheduler, register-pressure oracle,
  or benchmark replacement.
- Do not rewrite a construct merely to silence a diagnostic without a static semantic
  proof and a LuaJIT-enabled benchmark.
- Do not make `@jit` imply `@aot`, or share eligibility catalogs between two different
  compilers. They remain mutually exclusive execution contracts.
- Do not make runtime profile results part of whether source checks. The same source
  and target check identically without running the program.
- Do not retain unstable raw recorder strings as diagnostic identities or public API.

## Exact `@jit` contract

Clarify `@jit` as a checked absence-of-blockers contract for the selected LuaJIT
profile:

> Every reachable loop and operation in this visible checked body avoids the catalogued
> unconditional recorder blockers that Nupp can attribute statically. The annotation
> does not assert that the body runs, becomes hot, receives stable runtime types, or
> remains compiled for every input.

The checker follows statically resolved Nupp calls using the same call identities and
effect summaries used elsewhere. It reports the call path to a blocker. An unresolved
dynamic call is a conditional risk, not fabricated proof that every possible callee is
bad. A bodyless or gradual declaration may state only the existing trusted FFI and
effect facts; it cannot assert unknown bytecode recordable.

`jit.off(function)` is an explicit boundary. A disabled callee is allowed from an
ordinary function because the interpreter transition is the requested behavior. An
`@jit` function calling it reports that the annotated hot path deliberately leaves
compiled code unless the call is statically unreachable.

This wording preserves what the implemented checks can guarantee and removes the
stronger misleading reading that `@jit` forces runtime compilation. Adding a newly
catalogued unconditional blocker may make an annotated function fail in a later
compiler release. Therefore the catalog version enters the language-version and
interface contract, and additions require migration notes with a working alternative
or an explicit `jit.off` boundary.

## Trace profile and target identity

A verdict is relative to a trace profile:

```text
TraceProfile {
    luajitRevision
    architecture
    operatingSystem
    enabledRecorderFeatures
    bytecodeSchema
    reasonCatalogVersion
}
```

The normal host command uses the compiler-owned pinned VM. A target build uses the
target profile selected by its stub and platform configuration. Rules common to every
supported target are shared; target-specific recorder limitations are keyed explicitly.
Cross-checking never executes target code or assumes the build host's machine features.

The trace profile is part of `bc --check` JSON, build metadata when `@jit` occurs,
incremental keys for trace verdicts, and runtime trace reports. Two reports from
different revisions are not silently merged.

Nupp supports only profiles backed by a pinned LuaJIT source and executable fixtures.
An unknown external LuaJIT may run ordinary generated Lua, but a build requiring
`@jit` must select a supported profile or report that the contract cannot be checked.

## One normalized reason registry

Each reason record contains:

```text
TraceReason {
    id                  stable Nupp identity
    class               blocker | risk | stop
    targets             supported trace profiles
    sourcePredicate     optional checked-source fact
    bytecodePredicate   optional opcode/control-flow fact
    runtimeMatcher      optional VM event/error mapping
    sourceOwner         source node to underline
    explanation
    repair              only when semantics-preserving and specific
    lint                optional NUPP code and default level
    contractSeverity
}
```

`NUPP2514` and `NUPP2515` become entries in this registry rather than parallel
source and bytecode implementations. Existing `NUPP2707` remains the `@jit` contract
error family and cites the normalized reason. New reasons reserve lint codes only when
they are useful during ordinary checking; bytecode-only checks may use stable
`JIT-*` reason identities without filling the lint registry with diagnostics that
cannot arise from the checked CST.

Raw VM strings such as `NYI: bytecode FNEW` are retained as report detail but map to a
stable reason such as `jit/loop-function-construction`. A raw reason unknown to this
compiler is still reported as `jit/runtime-unknown`, with VM revision and raw payload;
it does not receive guessed advice.

The registry is data consumed by diagnostics, `nupp explain`, `bc --check --json`,
runtime CSV/JSON, documentation, and tests. There is one target predicate and one repair
per identity.

## Static analysis

### Work on the generated artifact

Traceability depends on the bytecode LuaJIT records, including code introduced by Nupp
lowering. `bc --check` therefore checks the exact generated artifact at the selected
optimization level. It builds a control-flow graph per prototype, identifies loop
headers and repeatable regions, and classifies instructions and resolved calls in each
region against the trace profile.

Source semantic facts are attached before erasure:

- resolved declaration and intrinsic identities;
- FFI signature, callback, vararg, retain/release, and calling-boundary facts;
- function construction and capture identities;
- table shape, allocation, raise, suspension, and external effects where proven;
- direct call graph and `jit.off` boundaries;
- generated operation ownership and optimization remarks; and
- authored source span for every generated bytecode range.

The bytecode pass consumes those published facts. It does not reconstruct an FFI
signature from generated Lua text or infer source capture relationships from opcode
names.

### Initial blocker catalog

Begin with behavior already proved and shipped:

- function construction (`FNEW`) in a repeatable loop;
- upvalue closing (`UCLO`) in a repeatable loop;
- exact unsupported variadic FFI forms, keyed by argument, result, ABI, and target
  predicates; the broader existing `jit-boundary` policy remains a conservative risk;
- Lua callbacks passed through C in a trace-unsafe direction; and
- an explicit operation whose pinned declaration is known to disable or flush the JIT
  inside the annotated region.

Then add one reason at a time from a deterministic VM fixture. Candidate categories
include unsupported bytecodes, non-yieldable/protected boundaries, recorder limits,
and target-specific FFI forms. A raw abort seen once in an application is evidence to
investigate, not enough to generalize a static rule.

Each unconditional rule requires:

1. a minimal generated-Lua fixture on every claimed trace profile;
2. bytecode inspection showing the stable operation being classified;
3. repeated isolated VM runs showing the recorder refuses it whenever reached;
4. a neighbouring accepted fixture; and
5. a source example whose proposed repair preserves answers and improves a measured
   hot workload.

Conditional risks may be reported in inspection output without failing `bc --check`.
They become default lints only after their precision and usefulness are measured.

### Loops, functions, and calls

A blocker belongs to the smallest repeatable loop whose recording it prevents. If no
loop encloses it, inspection reports the function operation but `bc --check` does not
claim runtime cost until a trace root can reach it. `@jit` is stronger: its contract
checks all reachable operations because a caller may form a root through the function.

The CFG records whether a hard blocker must be reached on every repeatable path or may
be reached on only some. Only the former supports the claim that the loop cannot form a
root trace. `@jit` rejects either because its contract covers every statically reachable
checked path, but a may-reach diagnostic says that a trace taking the path aborts rather
than claiming that every path stays interpreted.

Direct checked calls carry the callee verdict and a bounded call path. Recursive SCCs
reach a fixed point over reason sets. Unknown calls remain risks. A blocker under a
constant-dead or type-impossible branch is omitted only when the ordinary optimizer
has removed that branch from the checked generated artifact; trace checking does not
invent a second dead-code proof.

Hot reload invalidates cached verdicts when a function body, direct callee interface,
trace profile, optimization level, or generated bytecode fingerprint changes. A reload
still flushes affected VM traces as today; static checking does not try to preserve
machine code across replacement.

## Runtime observation without source injection

`profile.trace()` and `nupp run --jit-aborts` continue attaching one process-wide
LuaJIT trace callback. They do not alter generated prototypes. The callback receives
recorder events, maps their prototype/PC and raw error through the reason registry,
and aggregates:

- normalized reason and raw VM detail;
- abort, retry, and blacklist count;
- source path, line, and generated prototype identity;
- trace profile and hot-reload generation;
- optional current zone; and
- whether the same site has a static blocker, conditional risk, or no static match.

The callback runs only on recorder events, not on each iteration or field access. It
still has nonzero profiling cost and must be stopped after the interesting window.
When no session exists, no callback is attached and no trace aggregation state is
allocated.

Zones remain explicit. Recognized `zone.push`/discarded `zone.pop` forms retain their
existing inline lowering, but trace reporting works without them. The plan adds no
automatic function or loop zones.

Sampling and abort collection may run together. Correlation ranks sites that are both
sampled interpreted and observed aborting; it does not claim that an abort caused every
interpreted sample. Reports preserve the two measurements separately and show the
inference as a ranking.

## Commands and output

Keep `bc --check` as the deterministic static command:

```text
./bin/nupp bc --check src/physics.nupp
./bin/nupp bc --check --json src/physics.nupp
```

Extend its JSON schema with trace profile, prototype, loop, reason identity, class,
source span, bytecode PC/opcode, call path, and repair. Exit 1 only when a
must-reach unconditional blocker prevents the repeatable loop from completing a root
trace or an `@jit` contract fails. A may-reach blocker and a conditional risk remain
visible without silently changing CI status; add an explicit flag if callers later
need either to fail.

Ordinary `nupp check` reports configured trace lints and all `@jit` contract errors. It
does not run a second LuaJIT process. Source predicates decide the common checks. When
an annotated module needs a bytecode-only contract rule, checking may generate its
erased chunk in memory and ask the compiler-owned VM to compile, but not execute, that
chunk; it then decodes only the annotated prototypes. The selected trace profile still
decides whether an opcode is a blocker. Bytecode-only reasons outside `@jit` are
deferred to `bc --check` unless a manifest opts a target into project-wide trace
checking.

`nupp run --jit-aborts` keeps CSV compatibility and gains `--json`. A correlated report
may accept the static `bc --check --json` artifact from the same build key or compute it
after the run. A fingerprint mismatch reports two separate views instead of joining
stale static facts to new code.

### Manual function inspection in editors

Expose the same static query at one source position as `nupp lsp trace-check --json
FILE LINE COLUMN` and a `$/nupp/traceCheck` language-server request. The query selects
the smallest enclosing whole function or method, checks it and its statically resolved
checked callees exactly as `@jit` would, and reads the editor's unsaved overlay. It does
not edit in a temporary annotation, launch a second checker, attach a trace hook, or
persist a contract.

The VS Code extension contributes **Nupp: Check Function for JIT Trace Blockers** to the
Command Palette and editor context menu and offers the same operation as a lightbulb
action inside a function. Findings appear in a dedicated, temporary **Nupp JIT Check**
diagnostic collection with clickable blocker and call-path locations. The collection is
cleared when that document changes or another manual query replaces it. A successful
query says that no known static blocker was found for the selected profile without
claiming that the function becomes or remains compiled.

When the selected declaration may carry the annotation, the result offers **Add `@jit`
to keep checking this function** as a separate source edit. The one-shot check is the
investigation surface; adding `@jit` opts the function into continuous, transported,
non-suppressible enforcement.

Optimization remarks use the same reason identity when a pass rewrites or declines an
NYI-avoidance transformation:

```text
OPT-?: declined loop-function lifting at physics.nupp:42
reason: closure reads iteration value `body`
trace consequence: jit/loop-function-construction
```

The repair remains owned by the trace reason, not copied into the optimization pass.

## Rewriting policy

Trace awareness diagnoses first. A rewrite lands only when all of these hold:

- ordinary semantics, error order, effects, ownership, stack traces, and source lines
  are statically preserved;
- the rewrite removes a normalized unconditional blocker;
- JIT-on and JIT-off answers agree before and after;
- a traced benchmark shows a material win on the motivating workload; and
- `--remarks` identifies both the applied and declined cases.

Loop-invariant noncapturing function lifting already has a mechanically safe subset.
A closure that captures the iteration cannot be rewritten by silently changing its
capture into shared mutable state. Variadic FFI may move behind a `jit.off` helper only
when call/traceback changes are part of an explicit source or compiler contract. The
trace engine itself performs no rewrite.

## Deterministic tests

Static verdicts are tested from bytecode and semantic fixtures, not by waiting for a
hot loop to happen to abort. Every reason has:

- positive and neighbouring negative generated-bytecode fixtures;
- source attribution and repair fixtures;
- `@jit`, lint, and `bc --check` agreement;
- JSON Schema validation and stable reason identity; and
- target-profile inclusion/exclusion cases.

Runtime mapping tests feed recorded VM callback payloads into the normal registry and
aggregation path. A smaller process-isolated integration matrix pins `hotloop`, flushes
before loading a unique fixture, and verifies the selected supported LuaJIT emits a
compatible event. Static correctness never depends on that integration test's count or
timing.

Replace the flaky `traceRecordsWhereTheCompilerGaveUp` shape called out in plan 019:
the unit test owns a normalized recorded event, while the isolated VM compatibility
test answers only whether the pinned hook protocol still matches. An application trace
attempt is not an oracle for compiler checking.

## Implementation order

### T0 — Freeze current answers

- Record `@jit`, `NUPP2514`, `NUPP2515`, `bc --check`, profiler CSV, and explain output
  for the existing FFI and loop-closure fixtures.
- Record generated bytecode and source attribution at `-O0` and `-O1`.
- Record check/build/bc timing, emitted bytes, and no-profiler runtime baselines.
- Version the current compiler-owned LuaJIT trace profile.

### T1 — Reason registry and trace profile

- Introduce stable normalized reason records and one target predicate.
- Move existing FFI and loop-closure explanations into the registry without changing
  their codes or default levels.
- Publish trace profile and reason catalog versions in JSON and cache keys.
- Make unknown runtime reasons round-trip without guessed classification.

### T2 — Generated-bytecode control flow

- Build prototype CFGs, identify repeatable loop regions, and attach exact source and
  generated-operation identities.
- Make `bc --check` consume the reason registry and emit structured call/loop paths.
- Check the exact optimization-level artifact and invalidate on its fingerprint.
- Prove existing source and bytecode checks agree before deleting either duplicate.

### T3 — `@jit` fixed point

- Propagate unconditional blocker sets through resolved direct checked calls and
  recursive SCCs.
- Compile annotated generated chunks in memory, without executing them, only when a
  bytecode predicate cannot be decided from published source/lowering facts.
- Respect `jit.off`, unreachable generated branches, bodyless trust boundaries, and
  conditional unknown calls.
- Update the annotation reference to the precise absence-of-blockers contract.
- Add LSP hover and code actions showing the call path and specific repair.
- Add the position-based one-shot trace query and CLI operation, sharing the same root
  selection, fixed point, trace profile, and finding serializer as `@jit`.

### T4 — Runtime normalization and correlation

- Map `jit.attach` events to normalized reasons, prototype/PC, source, profile, reload
  generation, and optional zone.
- Add JSON beside compatible CSV and fingerprint-safe static correlation.
- Rank sampled interpreted plus aborting sites while preserving raw measurements.
- Replace the flaky profiler unit with recorded-event and isolated-protocol tests.

### T5 — Catalog expansion and measured repairs

- Inventory aborts from the compiler, stdlib, Tecs, and benchmark suite by raw reason.
- Promote only deterministic unconditional cases through the five-rule evidence gate.
- Add conditional risks to inspection before considering default lints.
- Implement NYI-avoidance rewrites individually under the optimization benchmark and
  semantics policy.

No phase makes runtime observation load-bearing for static correctness.

## Performance and compatibility gates

- With no profiler active, generated Lua and bytecode are byte-identical before and
  after this plan except for independently approved repairs.
- Ordinary `nupp run` attaches no trace hook and allocates no trace report state.
- `nupp check` without `@jit` or enabled trace lints may regress by at most 2% warm and
  5% cold; it should not decode bytecode it does not need.
- `bc --check` may pay for bytecode CFG construction but must cache per prototype and
  complete the compiler, stdlib, and Tecs target inside the existing command's useful
  interactive budget.
- `@jit` fixed-point summaries add at most 5% to public interface size and affected
  incremental invalidation.
- Trace profiling overhead is measured separately and documented; it is never compared
  to an uninstrumented run as though free.
- CSV remains readable by existing consumers; new normalized fields are additive or
  versioned.
- A supported trace profile is not changed in place. LuaJIT revision or catalog changes
  create a new identity and invalidate cached verdicts.

## Verification matrix

Tests must prove:

- ordinary builds and runs receive no instrumentation or trace hook;
- source, bytecode, `@jit`, lint, explain, and runtime mapping share one reason identity;
- unconditional blockers exit 1 from `bc --check` and conditional risks do not;
- lowered compiler-generated blockers are attributed to the authored construct;
- side-effect-free expected stops do not become warnings;
- unknown raw VM reasons remain visible and receive no invented repair;
- direct calls and recursive SCCs propagate blocker paths without infinite expansion;
- the manual LSP/CLI query selects the smallest enclosing method, reads unsaved text,
  returns the same findings as an equivalent `@jit` check, and changes no source;
- dynamic calls remain risks rather than false blockers;
- `jit.off` boundaries and `@aot` mutual exclusion retain their current semantics;
- optimization level, target profile, hot reload, and body changes invalidate the right
  verdicts;
- source lines and prototype PCs correlate only under matching build fingerprints;
- sampling/abort correlation preserves both underlying measurements;
- JIT-on and JIT-off program answers remain identical;
- process-isolated supported-profile fixtures validate every static catalog entry; and
- the compiler, stdlib, Tecs, workers, hot reload, profiler, AOT, and fixpoint suites
  retain their existing behavior.

## Completion criteria

This plan is complete when:

- one versioned registry owns every static and observed trace reason;
- `bc --check` deterministically checks exact generated loop bytecode;
- `@jit` has a precise, transported absence-of-blockers contract;
- VS Code and `nupp lsp trace-check` can inspect one function without persisting that
  contract;
- trace aborts map to stable source-level reasons without source instrumentation;
- runtime evidence and sampling rank problems without affecting checking;
- the flaky timing-dependent profiler test is removed;
- every catalogued blocker has positive, negative, target, attribution, and VM evidence;
- normal emitted code and runtime overhead are unchanged when profiling is off; and
- the full suite, fixpoint, bootstrap, target-profile, JIT-on/off, profiler, hot-reload,
  worker, Tecs, and performance gates pass.
