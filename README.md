# Nupp

Nupp is a gradually typed superset of LuaJIT's Lua dialect, implementing every
[LuaJIT 3.0 syntax extension](https://github.com/LuaJIT/LuaJIT/issues/1475) and
adding to them rather than subtracting (see
[grammar.abnf](docs/grammar.abnf)). Most of that syntax is written straight
through to the output, because LuaJIT 2.1 backported it; generated code needs
LuaJIT 2.1.1784535649 or newer. Its types are not always erased: `struct`
declarations lower to FFI cdata, with a fixed
layout and no hash lookups, and C headers import as typed declarations. Owned
resources are affine: an `affine(T, cleanup)` result records a deterministic
cleanup obligation, `takes` calls move it, borrows cannot escape, and
`pinned(T)` handles keep Lua-managed pointers alive across declared
`retains`/`releases` C calls. Raw-pointer reconstruction is confined to
explicit `unsafe do` blocks. See [ownership.md](docs/type-system/ownership.md)
for the complete contract reference. The [trace-aware
checker](docs/guides/jit-trace-checking.md) finds deterministic LuaJIT
recorder blockers in checked source and exact generated bytecode, transports
`@jit` contracts through resolved calls, and normalizes aborts observed in a
run.

A file's extension says which floor it is held to, so it is visible where the
file is rather than in a setting that governs everything at once: `.nupp` is
checked strictly, `.g.nupp` is the same typed syntax with the strict floor
down, and a plain `.lua` file is Lua, built and run unchanged, with the typed
layer refused in it. The marker is not part of the module's name, so
`require("models")` finds `models.g.nupp` and a file can change layer without
anything that requires it noticing. `nupp check --strict` holds every file to
the floor whatever it is called. See
[overview.md](docs/type-system/overview.md) for the type system this floor
sits under.

Compiler and lint output includes stable codes, source spans, related
locations, repair help, and structured fixes. See
[diagnostics.md](docs/reference/diagnostics.md) for the exact shape.

Nupp can also be linked as an application language: a C host can create or
attach a LuaJIT state, load inert checked components from memory, call named
exports through GC-safe handles, and keep ownership of its event loop. See
[embedding.md](docs/guides/embedding.md) for the full guide.

## Example

`comptime do ... end` is an expression whose value is computed while the file
is compiled and written into the generated Lua as a literal. A table built by
iterating cannot come from constant folding: folding rewrites an expression,
and a loop is not one. Here a `comptime function` helper builds a CRC-32
lookup table once, at compile time:

```nupp
local m = {}

local comptime function step(acc: integer): integer
    return acc & 1 ~= 0 and 0xedb88320 ~ (acc >> 1) or acc >> 1
end

const CRC32 = comptime do
    const entries = {}
    for byte = 0, 255 do
        local acc = byte
        for _ = 1, 8 do
            acc = step(acc)
        end
        entries[byte + 1] = acc
    end
    return entries
end

function m.checksum(text: string): integer
    local acc = 0xffffffff
    for index = 1, #text do
        acc = CRC32[((acc ~ text:byte(index)) & 0xff) + 1] ~ (acc >> 8)
    end

    return acc ~ 0xffffffff
end

return m
```

This is the language reference's own `comptime` example
(`nupp reference --section Comptime`). See
[comptime.md](docs/concepts/comptime.md) for the rules a block is held to. The
standard library ships a checked implementation as `nupp.data.crc32`, in
[init.nupp](src/nupp/data/init.nupp), for streaming or verifying checksums
rather than deriving the table by hand.
